# C题时间点、时间段与决策时序统一处理说明

## 0. 文档范围

本文件只规定时间标签、时间区间、数组编号、决策生效时刻、数据可得时刻和统计边界，不规定具体预测模型或优化策略。

SOC日循环或年终一致性、初始电量、冷启动购电量、储能参数、风险储备、预测插值算法、优化目标、结算计价公式及模型性能，由题面、用户最新要求和各问题的方法文件决定，不能从本文件推断。

发生时间口径冲突时，应依据题面、官方补充说明和用户明确要求核对；现有程序、论文或缓存不能反过来改变时间定义。右端点解释是本文的离散化约定，不声称题面逐字规定了“前十分钟平均功率”。

### 0.1 核心时间规则

1. 输入点 `00:10` 对应自然日00:00—00:10，是该十分钟段的右端标签。
2. 第 $d$ 日00:00制定的新计划第1段为当日00:10—00:20，第144段为次日00:00—00:10。
3. 计划段 $j=1,\ldots,143$ 对应当日输入列 $j+1$；第144段对应下一日输入第1列。
4. 自然日执行顺序为前一日计划第144段，加当日计划第1—143段。
5. 若允许06:00、12:00、18:00调整，其首个可调整计划段分别为 $j=36,72,108$。
6. 自然日统计按00:00—24:00；计划行统计按00:10—次日00:10，不能混用。
7. 未来实际观测不能进入此前的决策；已知价表、给定预测和已发布预报按其实际可得时刻处理。
8. 附件3预报的“未来第 $h$ 小时”指发布时刻之后的整点，不是一个小时区间。

本文件不扩展任何问题允许使用的附件，也不意味着所有问题都允许日内调整。

## 1. 时间步长、时间点和物理时间段

$$
\Delta t=10\text{ min}=\frac16\text{ h}.
$$

$\Delta t$ 是持续时间，不是时段编号。用 $i$ 表示自然日物理段编号，用 $j$ 表示计划行段编号，两者均从1开始。

对自然日 $d$，定义

$$
\tau_{d,0}=d\text{日 }00{:}00,\qquad
\tau_{d,i}=\tau_{d,0}+i\Delta t,
$$

$$
I_{d,i}=(\tau_{d,i-1},\tau_{d,i}],\qquad i=1,\ldots,144.
$$

$\tau_{d,144}$ 是次日00:00，附件写作 `0:00+1`，也就是当天24:00。

| 输入标签 | 物理段编号 $i$ | 对应区间 |
|---|---:|---|
| `00:10` | 1 | 00:00—00:10 |
| `00:20` | 2 | 00:10—00:20 |
| `06:00` | 36 | 05:50—06:00 |
| `06:10` | 37 | 06:00—06:10 |
| `12:00` | 72 | 11:50—12:00 |
| `18:00` | 108 | 17:50—18:00 |
| `23:50` | 143 | 23:40—23:50 |
| `0:00+1` | 144 | 23:50—次日00:00 |

本文统一采用左开右闭记法，以避免相邻区间重复归属。附件5的横线标签表示区间持续时间；端点开闭不改变积分，也不造成零时长端点的重复统计。

若输入功率作为对应区间的代表功率，十分钟电量为功率乘 $\Delta t$。这仅说明时间长度与单位换算；已是kWh的区间电量不得再乘时间步长。

## 2. 计划时间段及其唯一映射

第 $d$ 日00:00制定的第 $j$ 个计划段为

$$
J_{d,j}=
(d\text{日 }00{:}10+(j-1)\Delta t,\
d\text{日 }00{:}10+j\Delta t],
\qquad j=1,\ldots,144.
$$

| 计划段编号 $j$ | 对应区间 |
|---:|---|
| 1 | 当日00:10—00:20 |
| 35 | 当日05:50—06:00 |
| 36 | 当日06:00—06:10 |
| 71 | 当日11:50—12:00 |
| 72 | 当日12:00—12:10 |
| 107 | 当日17:50—18:00 |
| 108 | 当日18:00—18:10 |
| 143 | 当日23:50—次日00:00 |
| 144 | 次日00:00—00:10 |

计划轴与物理轴的映射为

$$
J_{d,j}=I_{d,j+1}\quad(j=1,\ldots,143),\qquad
J_{d,144}=I_{d+1,1}.
$$

输入行和计划行虽然都是144段，却不能同列硬配。

| 计划区间 | 对应实际输入点 |
|---|---|
| 当日00:10—00:20 | 当日 `00:20` |
| 当日06:00—06:10 | 当日 `06:10` |
| 当日12:00—12:10 | 当日 `12:10` |
| 当日18:00—18:10 | 当日 `18:10` |
| 当日23:50—次日00:00 | 当日 `0:00+1` |
| 次日00:00—00:10 | 次日 `00:10` |

这个映射规定的是执行后的数据对应关系，不意味着制定计划时已经知道这些未来实际值。

## 3. 决策时刻与数据可得时刻

### 3.1 每日00:00

第 $d$ 日00:00：

- 已知截至该时刻已经到达的历史实际数据、当前状态、已发布且允许使用的预测，以及前一日留下的当日首段承诺。
- 当日00:00—00:10执行前一日计划第144段。
- 新计划覆盖当日00:10—次日00:10，不重新决定已经由前一日承诺覆盖的首段。

当日输入点 `00:10` 的实际负载、光伏及该段执行后的状态，要到00:10才成为已完成数据，不能在00:00制定新计划时使用。

00:00制定计划时若需要00:10的状态，只能使用当时已知信息形成预测状态；真实00:10状态须在该段执行后取得。

### 3.2 日内调整边界

以下规则只适用于允许相应时刻调整的问题：

| 调整时刻 | 已结束的当日计划段 | 首个可调整段 | 首个调整区间 |
|---|---|---:|---|
| 06:00 | $j=1,\ldots,35$ | 36 | 06:00—06:10 |
| 12:00 | $j=1,\ldots,71$ | 72 | 12:00—12:10 |
| 18:00 | $j=1,\ldots,107$ | 108 | 18:00—18:10 |

例如，06:00可使用输入点 `06:00`，它对应此前已结束的05:50—06:00；不能使用输入点 `06:10` 的未来实际值。

本文采用零数据传输和零计算延迟假设：边界时刻到达的数据与发布的预测立即可用；允许在该边界发布的调整立即作用于从该边界开始的区间。

00:00新计划固定从00:10开始，是计划行的时间定义，不据此推导出所有决策都有十分钟计算延迟。若另行引入实际通信或计算延迟，应按结果实际发布时间重新确定首个可生效段。

某个区间使用其开始时刻之前（包括同一边界时刻）最后一次已经发布、允许生效的购电承诺。没有新承诺时沿用此前有效值。数据或预报的到达，不自动意味着该问题允许重新发布购电计划。

### 3.3 防止时间上的数据泄露

未来实际观测、已发布预测和提前已知的价表是不同对象：

- 对需要执行或观测后才产生的实际值，其对应区间结束且数据到达后才能进入信息集。
- 预测可对应未来时刻，只要它在决策时刻已经发布并且该问题允许使用。
- 提前已知的固定价表可以覆盖未来区间，不属于未来实际观测泄露。

是否读取全年数组本身不是判定标准；关键是计划函数能否访问决策时刻尚不可得的实际值。离线结算用到未来实际值，不能使它反向进入此前计划。

## 4. 附件3预报的时间轴与覆盖范围

附件3每天00:00、06:00、12:00、18:00发布未来24小时整点预报。发布时刻 $T$ 的“预报 $h$ 小时”对应

$$
T+h\text{小时},\qquad h=1,\ldots,24.
$$

| 发布时刻 | 预报字段 | 对应未来时刻 |
|---|---|---|
| 当日06:00 | 预报1小时 | 当日07:00 |
| 当日18:00 | 预报6小时 | 次日00:00 |
| 当日18:00 | 预报7小时 | 次日01:00 |

它们是整点点预测，不是小时区间累计量。转换为十分钟预测时，目标点必须按对应物理段的右端时刻定位；具体插值或预测算法由方法文件规定，本文件不选择算法。

若某方法使用发布时刻的最新实际输入点作为时间锚点，则00:00对应前一日 `0:00+1`，06:00、12:00、18:00分别对应当日同名输入点。缺少锚点时的取值由方法文件规定，不能使用发布时刻以后的实际值补齐。

00:00发布的第24小时整点是次日00:00；当天计划第144段的右端点却是次日00:10，超出该批整点预报的最远节点10分钟。覆盖不足的预测值应由方法文件明确处理，不能默认取得未来实际值，也不能由本文件规定其数值。

较晚发布的预报可能覆盖同一跨日目标点，须按“目标绝对时刻减发布绝对时刻”重新定位，不能只按钟面小时查找。

## 5. 自然日统计与跨计划日拼接

自然日 $d$ 的执行顺序为

$$
J_{d-1,144},J_{d,1},\ldots,J_{d,143}.
$$

| 自然日统计区间 | 对应计划段 | 段数 |
|---|---|---:|
| 00:00—04:00 | 前一日 $J_{d-1,144}$ 加当日 $J_{d,1:23}$ | 24 |
| 04:00—08:00 | $J_{d,24:47}$ | 24 |
| 08:00—12:00 | $J_{d,48:71}$ | 24 |
| 12:00—16:00 | $J_{d,72:95}$ | 24 |
| 16:00—20:00 | $J_{d,96:119}$ | 24 |
| 20:00—24:00 | $J_{d,120:143}$ | 24 |

状态的时间标签定义为：

- 当日00:00状态：执行前一日计划第144段之前的状态。
- 当日00:10状态：执行前一日计划第144段之后的状态。
- 当日24:00状态：执行当日计划第143段之后的状态，也是次日00:00边界的状态。

上述定义不规定首末状态是否相等，也不规定任何日循环或年终目标。

计划行合计覆盖00:10—次日00:10；自然日合计覆盖00:00—24:00。两种合计须明确标注，不能统一称为未说明边界的“全天合计”。当日计划第144段不能纳入当日自然日储能统计。

## 6. 示例：2025年2月1日00:00—00:20

| 执行区间 | 对应实际输入点 | 购电承诺来源 | 状态时间标签 |
|---|---|---|---|
| 2月1日00:00—00:10 | 2月1日 `00:10` | 1月31日计划第144段 | 段首00:00，段末00:10 |
| 2月1日00:10—00:20 | 2月1日 `00:20` | 2月1日计划第1段 | 段首00:10，段末00:20 |

```text
2月1日00:00
  已取得截至1月31日24:00的数据及00:00状态
  当日首段执行1月31日计划第144段
  制定2月1日00:10—次日00:10的新计划
         ↓
2月1日00:10
  首段结束，输入点00:10的实际数据成为可得数据
  取得00:10真实状态
  开始执行2月1日计划第1段
         ↓
2月1日00:20
  当日计划第1段结束，输入点00:20的实际数据成为可得数据
  取得00:20真实状态
```

00:00计划不能使用当日 `00:10` 或 `00:20` 的未来实际值。执行后的数据对应关系，与计划时允许使用的信息不是同一件事。

## 7. 程序数组与下标换算

数学编号 $i,j$ 从1开始；Python数组下标从0开始。

| 区间 | 物理下标 `physical_slot0` | 计划下标 `plan_slot0` |
|---|---|---|
| 当日00:00—00:10 | 当日0 | 前一日143 |
| 当日00:10—00:20 | 当日1 | 当日0 |
| 当日06:00—06:10 | 当日36 | 当日35 |
| 当日23:50—24:00 | 当日143 | 当日142 |
| 次日00:00—00:10 | 次日0 | 当日143 |

阶段边界分别为：

```python
PHYSICAL_STAGE_START = {0: 0, 6: 36, 12: 72, 18: 108}
PLAN_STAGE_START = {0: 0, 6: 35, 12: 71, 18: 107}
```

物理轴的00:00下标0表示自然日首段，不表示当日新计划可以修改该段。

以下函数使用日期对象；跨日运算明确为一天：

```python
from datetime import timedelta

one_day = timedelta(days=1)

def actual_source_position(decision_day, plan_slot0):
    """计划日期与零基下标 -> 实际输入日期与物理零基下标。"""
    if not 0 <= plan_slot0 < 144:
        raise ValueError("plan_slot0 must be in [0, 143]")
    if plan_slot0 < 143:
        return decision_day, plan_slot0 + 1
    return decision_day + one_day, 0

def calendar_execution_plan(calendar_day, physical_slot0):
    """实际执行日期与物理零基下标 -> 承诺所属计划日期与下标。"""
    if not 0 <= physical_slot0 < 144:
        raise ValueError("physical_slot0 must be in [0, 143]")
    if physical_slot0 == 0:
        return calendar_day - one_day, 143
    return calendar_day, physical_slot0 - 1
```

若程序使用整数日期序号，可用序号加减1；不能把日期对象、日期序号和时间戳混用。

内部字段至少应能区分输入日期、输入时间点、物理区间、计划日期、计划区间、发布时间和实际数据到达时刻。这些是内部时间信息，不要求向附件5增加正式列。

## 8. 起止日期与跨年边界

### 8.1 仿真起点与正式输出起点

2025年1月1日00:00是年度数据起点，2025年2月1日是问题2—4正式输出起点，两者不是同一概念。

采用1月预运行时，1月31日计划第144段自然衔接2月1日00:00—00:10；不能因为正式输出从2月开始，就把2月1日当作新的时间起点并丢掉前一日承诺。

若仿真从1月1日开始，由于不存在2024年12月31日计划，首段需要独立的冷启动处理。购电量和状态初值由模型文件决定，本文件只指出缺少前一日承诺这一时间边界事实。

重复典型日采用周期衔接时，其自然日执行仍由前一周期末计划段加当前周期前143段组成；具体周期约束不在本文件规定。

### 8.2 2025年12月31日末计划段

12月31日计划第144段作用于2026年1月1日00:00—00:10，应保留计划输出。

2025年自然日统计在12月31日24:00结束，即执行完12月31日计划第143段。第144段属于2026年，不进入2025年自然日统计。

若缺少2026年首段实际数据，应标记实际值不可得；不能用2025年末段实际值冒充该跨年段实测。是否采用代理预测及怎样单列费用，由对应方法和结果说明决定。

## 9. 时间核对清单

- [ ] 输入点 `00:10` 对应00:00—00:10，而不是后十分钟。
- [ ] 当日计划第1段对应当日输入点 `00:20`。
- [ ] 当日计划第144段对应下一日输入点 `00:10`。
- [ ] 自然日首段使用前一日计划第144段。
- [ ] 允许的06:00调整从数学计划段 $j=36$、计划零基下标35开始。
- [ ] 物理零基下标36与计划零基下标35表示同一06:00—06:10区间。
- [ ] 预报发布时间、预报目标时刻及实际观测到达时刻分开保存。
- [ ] 未来整点预报未被解释为小时区间累计量。
- [ ] 计划函数不能访问决策时刻尚不可得的实际数据。
- [ ] 已结束的当日区间可以进入后续允许的决策，不只限于前几日历史。
- [ ] 六个自然日统计块各24段，合计144段，无遗漏、无重复。
- [ ] 状态标签区分段首、段末和00:00/24:00边界。
- [ ] 仿真起点、预运行期和正式输出起点已区分。
- [ ] 跨年末计划段未重复计入2025年自然日统计。

## 10. 时间解释的依据与适用边界

附件1、2、4的标签从 `00:10` 到 `0:00+1`；题面说明 `0:00+1` 即次日00:00。按本文右端点约定，输入行覆盖自然日完整24小时。

附件5的计划购电行从 `0:10-0:20` 到次日 `0:00-0:10`；储能表却从 `0:00-4:00` 到 `20:00-24:00`。因此必须保留输入物理轴与计划轴，不能因为数组同为144列就默认同下标对应同区间。

本文件依据 `C题.pdf`、`C题.md` 和附件1—5的时间标签与格式整理。预测算法、物理约束、费用计算、可用附件范围和结果数值不由本文件决定。
